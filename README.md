# Hackalem AI

### Что изменилось в обязанностях после реорганизации — и где это написано?

Hackalem AI сравнивает организационные документы **до** и **после** изменений. Он извлекает подразделения и функции, сопоставляет их по смыслу и подсвечивает возможную потерю функций, дублирование работы и пересечение ответственности. Каждый вывод сопровождается цитатой из исходного документа, чтобы человек мог его проверить.

> **Пример:** до реорганизации отдел закупок вёл реестр договоров аренды. В документах после реорганизации соответствующая функция не найдена. Система покажет это как _потенциальную_ потерю функции и укажет исходную строку. Окончательный вывод остаётся за экспертом.

## Как это работает

```text
PDF / DOCX / XLSX «до» и «после»
             ↓
извлечение текста, подразделений и функций
             ↓
сопоставление подразделений и обязанностей
             ↓
сводка изменений → выводы → цитаты и местоположение в документе
```

Продукт ищет три вида ситуаций:

| Ситуация                        | Что проверить                                                                                                        |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| **Потеря функции**              | Обязанность была в документах «до», но ей не найдено достаточного соответствия в предоставленных документах «после». |
| **Дублирование**                | Похожие функции указаны у разных подразделений после изменений.                                                      |
| **Пересечение ответственности** | Разные подразделения выполняют потенциально конфликтующие роли по сходному объекту, например исполнение и контроль.  |

Для каждого вывода доступны объяснение, оценка уверенности и доказательства: имя файла, страница PDF или лист XLSX, раздел или абзац, а также точная цитата. Сервис проверяет, что цитата действительно присутствует в извлечённом фрагменте документа.

## Запуск с анализом содержимого

**Понадобятся:** Node.js **24+**, npm и API ключ OpenAI для LLM и embeddings. Команды ниже запускаются из корня репозитория в **трёх терминалах**. Ключ указывается только в `ai-service/.env`.

**Терминал 1 — AI Service**

```bash
cd ai-service
npm ci
cp -n .env.example .env
# Откройте .env и заполните LLM_API_KEY
npm start
```

**Терминал 2 — backend**

```bash
cd backend
npm ci
cp -n .env.example .env
# В .env установите USE_MOCK_AI=false
npm run dev
```

**Терминал 3 — интерфейс**

```bash
cd frontend
npm ci
npm run dev
```

Откройте [http://localhost:5173](http://localhost:5173). Если вы меняете `.env`, перезапустите соответствующий сервис.

### Проверка решения за несколько минут

1. На главной странице нажмите **«Начать анализ»**.
2. В поле **«До»** загрузите [`examples/before.xlsx`](examples/before.xlsx), в поле **«После»** — [`examples/after.xlsx`](examples/after.xlsx).
3. Нажмите **«Запустить анализ»** и дождитесь страницы результата. Запрос может выполняться до десяти минут.
4. Просмотрите вкладки **«Обзор»**, **«Подразделения»**, **«Функции»** и **«Выводы»**. В примере можно проверить судьбу функции ведения реестра договоров аренды и распределение обработки заявок на закупки между подразделениями.
5. Откройте вывод: на странице показаны объяснение и цитаты из загруженных файлов. Сверьте цитату с исходной строкой XLSX.

Результат зависит от ответов моделей и полноты документов; отсутствие вывода само по себе не доказывает отсутствие проблемы.

### Запуск без API ключа

Чтобы проверить загрузку файлов, сохранение анализов и интерфейс, запустите только backend и frontend по командам выше, **оставив** `USE_MOCK_AI=true` из `backend/.env.example`. AI Service в этом режиме не нужен. После запуска анализа появится демонстрационный результат **без разбора содержимого и без выводов**. Для проверки самой идеи сравнения нужен запуск с AI Service.

## Состав проекта

| Каталог                      | Назначение                                                      | Технологии                                         |
| ---------------------------- | --------------------------------------------------------------- | -------------------------------------------------- |
| [`frontend/`](frontend/)     | Загрузка документов, сводка, функции и доказательства           | React 19, TypeScript, Vite, Tailwind CSS           |
| [`backend/`](backend/)       | API, загрузка файлов, хранение и запуск анализа                 | Node.js 24+, Fastify, SQLite                       |
| [`ai-service/`](ai-service/) | Разбор документов, извлечение, сопоставление и проверка выводов | Node.js, PDF.js, Mammoth, ExcelJS, OpenAI API, Zod |
| [`bot/`](bot/)               | Альтернативный интерфейс через Telegram                         | Python, python-telegram-bot, httpx                 |

Frontend обращается к backend через Vite proxy `/api`. Backend хранит файлы и результаты в `backend/data/`, а AI Service получает документы на время обработки и возвращает результат. Telegram-бот использует тот же backend; [инструкция по запуску бота](bot/README.md).

**Адреса:** [интерфейс](http://localhost:5173) · [backend health](http://localhost:3000/health) · [Swagger UI](http://localhost:3000/docs/) · [AI Service health](http://localhost:8001/health).

## Автоматические проверки

После установки зависимостей в соответствующих каталогах:

```bash
cd backend && npm test
cd ../ai-service && npm test
cd ../frontend && npm run build
```

Тесты AI Service используют локальные подставные ответы моделей, поэтому для них API ключ не требуется. Отдельный полный сценарий backend проверяет создание анализа, загрузку и получение результата. Тесты бота после установки зависимостей по [инструкции](bot/README.md) запускаются без Telegram токена: `cd bot && python3 -m unittest test_bot.py`.

## Границы текущей версии

- Поддерживаются PDF с текстовым слоем, DOCX и XLSX. Для сканов PDF нужен OCR, которого пока нет.
- Максимальный размер загружаемого через backend файла — **20 МБ**. Нужен минимум один файл с каждой стороны.
- Вывод «функция потеряна» означает, что соответствие не найдено **в загруженных документах**. Это не юридическое заключение; пороги сопоставления требуют проверки на размеченных данных.
- API backend пока без авторизации и рассчитан на локальную демонстрацию. Не выставляйте его в публичную сеть с рабочими документами.

Подробности: [backend API](backend/README.md) · [AI Service и параметры моделей](ai-service/README.md) · [Telegram-бот](bot/README.md).

### Скорость анализа и повторный запуск

Веб запускает анализ через `POST /api/analyses/:id/run?background=true` (HTTP 202)
и опрашивает статус. Открытая вкладка и длительное HTTP-соединение для выполнения
не нужны. Обычный `/run` сохраняет синхронный ответ для Telegram.
Ошибки сохраняются в анализе; на сайте доступен повторный запуск без загрузки файлов.
При перезапуске backend прерванные анализы помечаются как ошибочные. Один процесс
backend должен обслуживать свою SQLite-базу.

AI Service выполняет до четырёх задач извлечения/сопоставления одновременно,
не отправляет одинаковые тексты на embeddings повторно внутри анализа и сохраняет
успешные ответы провайдера в `ai-service/data/provider-cache/`.
Повторная загрузка тех же документов использует кэш с привязкой цитат к новым ID.
В ключ кэша входят модель, endpoint, учётные данные и содержимое запроса.
Ошибочные ответы не кэшируются; изменение модели или запроса вызывает новый платный запрос.

Кэш содержит данные, полученные из документов, хранится локально и исключён из Git.
Для очистки удалите `ai-service/data/provider-cache/`; для отключения задайте
`PROVIDER_CACHE_DIR=` в окружении AI Service. Структурированные логи показывают
этап, длительность, количество запросов и попаданий в кэш без текста документов.
Временные HTTP 429/502/503/504 повторяются максимум один раз; ошибки квоты и
таймауты автоматически не повторяются. Обрыв запроса backend отменяет работу AI Service.
